# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Forest Prana is a static, Latvian-language catalog shop (React 19 + TypeScript + Vite + MUI). There is no backend or payment flow: visitors build an order that becomes a pre-filled WhatsApp (`wa.me`) message. See [README.md](README.md) for the feature list and deployment (Netlify, `pnpm run build`, publish `dist`).

## Commands

```bash
npm run dev      # Vite dev server on :5173 (runs fetch-assets first via predev)
npm run build    # fetch-assets, then `tsc -b && vite build`
npm run lint     # oxlint (only rules-of-hooks and only-export-components are configured)
npm run fetch-assets
```

There is no test suite. `tsc -b` (part of `build`) is the type check. Both `package-lock.json` and `pnpm-lock.yaml` exist; Netlify uses pnpm, so keep both in mind when changing dependencies.

## Architecture

**All shop content lives in [src/data/products.ts](src/data/products.ts)**: product arrays (`oximeli`, `ziedes`, `citi`), vinegars (`etiki`), `images` (site-wide), `categories` (backgrounds/thumbs) and contact constants. [src/lib/catalog.ts](src/lib/catalog.ts) flattens these into one `catalog` array of `CatalogItem`s and derives everything the UI needs. Components read from `catalog`/`catalogById`, not from `products.ts` directly.

Things that span files and are easy to miss:

- **Descriptions are parsed by regex.** `parseDescription` in `catalog.ts` splits a product's plain-text `description` on blank lines and sorts chunks into composition (`Sastāvs:`), usage, cautions and general paragraphs, using Latvian keywords (`Lietošana`, `Brīdinājums`, `nedrīkst`, `grūtniec`, ...). The product dialog and the card excerpt render from this. Keep that wording convention when writing descriptions, or text lands in the wrong section.
- **Vinegars are a different shape** (`Vinegar`: no `id`, no description). Their ids are generated by `slug(name)`, and they all share `etikiBenefits`. The slug is also the URL hash, so renaming a vinegar changes its link.
- **Product `id` is a stable key**: it is the URL hash (`/#piladzu-oximels`, deep-linked by `App.tsx`), and the order key. Category ids (`/#oximeli`) filter the catalog.
- **Category data is split in two places**: display labels/blurbs and the `CategoryId` union are in `categoryMeta` (`catalog.ts`); background/thumb images are in `categories` (`products.ts`). Adding a category means touching both.
- **Order state** (`src/lib/order.tsx`) is a React context persisted to `localStorage` under `forest-prana-order-v1`. On load it drops sold-out and unknown product ids, so removing or renaming an `id` silently empties that line from returning visitors' orders. `soldOut: true` shows the "Pārdots" badge and blocks ordering.

## Images

Images live in `public/media/<category>/<product-id>.<ext>` (`oximeli`, `etiki`, `ziedes`, `citi`; non-product images in `site/`) and are referenced with `m('<category>/<file>')` in `products.ts`.

`scripts/fetch-assets.mjs` runs before `dev` and `build`. It scans `products.ts` for `m('...')` calls and, for any file missing on disk, downloads it from the original Canva host, using [scripts/media-map.json](scripts/media-map.json) to translate the local path to the Canva hash filename. Consequences:

- Existing files are never re-downloaded, and a failed download only warns (the build still succeeds with a broken image), so check the script output.
- When replacing a product photo with your own file, delete its entry from `media-map.json`; otherwise a missing file would be re-fetched as the old Canva image.
- Files in `public/media/` that no `m()` call references are not fetched or validated (some `citi/` photos are staged this way for products not yet in the catalog).
- Paths in `index.html` (favicon, hero preload) are hard-coded and not scanned by the script.
